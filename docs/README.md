# Технічна документація

## Контракт API — `openapi.yaml`

Опис усіх запитів, потрібних для 21 вимоги Must зі звіту (етап Е1б): маршрут, ролі, тіло запиту й відповіді, коди помилок, посилання на FR / UC / DG і дію, яку записують у журнал аудиту.

**Переглянути в зручному вигляді:**
- https://redocly.github.io/redoc/?url=https://raw.githubusercontent.com/andra023best/gedh/main/docs/openapi.yaml
- або https://editor.swagger.io → File → Import URL → `https://raw.githubusercontent.com/andra023best/gedh/main/docs/openapi.yaml`

**Позначення в операціях:**

| Поле | Значення |
|---|---|
| `x-fr`, `x-uc`, `x-dg` | вимоги, прецеденти й правила data governance зі звіту |
| `x-roles` | хто може виконати; `GUEST` — без входу, `SYSTEM` — службова задача |
| `x-audit` | дія, що записується в журнал аудиту |
| `x-priority: Should` | допоміжний маршрут, без якого сценарії Must не працюють |

**Як контракт пов'язаний з кодом.** Контракт — це домовленість, яку переглядає команда. Тест `backend/tests/test_contract.py` перевіряє, що файл — валідний OpenAPI 3.1, кожна операція має ролі, а всі вимоги Must покрито. Під час реалізації кожного етапу маршрути FastAPI мають відповідати контракту. Якщо вони розходяться, змінюємо контракт свідомо, з записом рішення в журналі.

Журнал рішень етапу розробки поки ведеться поза репозиторієм, у файлі `03_Розробка_сайту.md` командної папки.
