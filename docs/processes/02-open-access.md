# 2. Рівні доступу L0 і L1: що бачить гість і зареєстрований користувач

**Вимоги:** FR-07, FR-09 (каталог), FR-11 (вивантаження), FR-26 (перевірка доступу), FR-27 (позначка синтетичних даних) ·
**Прецеденти:** UC-04, UC-05 (частково), UC-16 · **Правила:** DG-03, DG-04, DG-05, DG-13.

**Код:** `backend/app/api/data.py`, `reference.py`; сторінки `frontend/src/pages/DataPages.tsx`.
**Тести:** `backend/tests/test_ingestion.py::test_open_data_view_requires_login_and_restricted_is_denied`.

## Рівні доступу (концепція §3.2)
| Рівень | Хто | Що доступно |
|---|---|---|
| **L0 — гість** | без входу | **лише «Про платформу»** (що це, звідки дані, рівні доступу, як отримати доступ), вхід, реєстрація, відновлення пароля. Карта, каталог і картки показників — з L1 (S-36) |
| **L1 — відкриті дані** | будь-який активний обліковий запис (після схвалення адміністратором) | **значення** 10 відкритих показників World Bank, IMF, BIS для 25 країн: **профіль країни, графіки, порівняння, рейтинг** (файл 11); профіль користувача |
| **L2 — закриті дані** | лише за чинним дозволом «країна × категорія × період» | значення закритого набору в межах дозволу (файл 7) |
| службові ролі | постачальник, адміністратор, DG-офіцер | власні набори; розгляд заявок; конектори й довідники (файл 12); перевірка й публікація наборів, журнал (файл 8) |

## Що бачить гість (L0) — з S-36
Рішення користувача (25.11): до входу людина не бачить функціоналу сайту — лише опис платформи. Так і ті, хто вже
подав заявку на реєстрацію, але ще не схвалений (увійти вони не можуть), бачать те саме, що гість.

| Сторінка / запит | Що відбувається |
|---|---|
| головна `/` і `/about` | текст «Про платформу»: що це, звідки дані, рівні доступу, як отримати відкритий і закритий доступ, як захищено; кнопки «Зареєструватися» й «Увійти» (`frontend/src/pages/AboutPage.tsx`) |
| меню | «Про платформу», «Увійти», «Реєстрація». «Каталог» і «Стан системи» гість не бачить («Стан системи» — лише адміністратор, T-02) |
| `/catalog`, `/indicators/{код}`, `/countries/{код}`, `/compare` | переадресація на вхід |
| `GET /api/catalog/datasets`, `/catalog/datasets/{id}`, `/coverage`, `/indicators/{код}` | **401** — з S-36 лише після входу (сесія або API-ключ) |
| `GET /api/countries`, `/categories`, `/indicators`, `/organizations` | **публічні** — потрібні формі реєстрації (країна, організація) і нічого не розкривають |
| `GET /api/datasets/{id}/observations` | **401** — значення лише після входу |

Каталог і покриття в журнал аудиту не пишуться — вони не містять значень (нотатки для розробки, розд. 6).

**Що L1 бачить замість гостя:** каталог (14 наборів, для закритих — країна, постачальник, «СИНТЕТИЧНІ ДАНІ», без значень),
карту покриття, картки показників (файл 11).

## Що бачить зареєстрований користувач (L1)
Сторінка **«Дані»** (`/data`): вибір показника → таблиця «країна × останні 10 років».

`GET /api/datasets/{id}/observations` — **перевірка доступу на кожному запиті** (UC-16):
1. токен дійсний, сесія не відкликана, статус `ACTIVE` (файл 1, крок 7);
2. **відкритий набір** — доступ дозволено будь-якому активному обліковому запису;
3. **закритий набір** — постачальник-власник, DG-офіцер або власник **чинного дозволу** (лише в межах його періоду);
   усім іншим **403 `ACCESS_DENIED`** і запис `DATA_VIEW / DENIED` у журнал (файл 7);
4. береться **чинна опублікована версія** (або конкретна — параметр `version`);
5. фільтри: `countries=UKR,POL`, `period_from`, `period_to`;
6. у журнал — `DATA_VIEW / SUCCESS`: хто, який набір, яка версія, скільки записів.

**Що містить відповідь:** значення з періодом і приміткою; версія й дата публікації; ліцензія;
**оцінка якості** (DQ-score і кількість попереджень); **джерело**: назва ряду (наприклад, «World Bank — WDI
(NY.GDP.MKTP.CD)»), адреса запиту до API, дата імпорту, SHA-256 сирої відповіді.

**Як показується:**
- **«н/д»** — джерело не має значення; інтерполяція не виконується (UC-05 EX1);
- **`*`** — примітка (наведіть курсор): «оцінка IMF WEO» для останнього року IMF або «ставка ЄЦБ (ряд BIS XM)»
  для країн єврозони;
- облікова ставка України та Єгипту — «н/д»: BIS їх не публікує (D-37).

## Звідки ці дані й наскільки свіжі
Імпорт з API джерел за розкладом кожного конектора (типово щопонеділка; GitHub Actions викликає планувальник
щодня о 03:00 UTC, S-37) і вручну — файл 12. Нова версія з'являється лише тоді,
коли джерело змінило значення. Деталі — у файлі 5.

## Що ще може зареєстрований користувач
- **Профіль**: що про нього зберігається й скільки; виправлення ПІБ і посади; нова версія згоди;
  видалення облікового запису або відкликання згоди — файл 1, крок 9.
- **Вивантажити відкриті дані** у CSV або JSON — кнопки на сторінці «Дані» (з метаданими й SHA-256, файл 7, крок 7).
- **Подати заявку на закриті дані** — лише представник верифікованої організації (файл 7).
