# 13. API-ключі: дані у ваших програмах і завантаження наборів без браузера

**Вимоги:** FR-12 (ключ аналітика для читання даних, Could), FR-37 (завантаження наборів постачальником через REST API, Could),
NFR-18 (60 запитів/хв на ключ), NFR-15 / NFR-20 (секрети лише у вигляді хешів) · **Прецеденти:** UC-07, UC-12.

**Код:** `backend/app/core/deps.py` → `api_user()`, `user_by_api_key()`, `require_api()`; `backend/app/api/me.py` (ключі);
`backend/app/core/ratelimit.py` → `check_key()`; профіль — `frontend/src/pages/ProfilePage.tsx` (`ApiKeys`).
**Тести:** `backend/tests/test_e6v.py::test_api_key_reads_data_and_is_limited`, `::test_provider_uploads_with_api_key`.

## Ідея одним реченням
Ключ — це «пароль для програми»: він діє **від імені власника з його роллю й дозволами**, але **лише на маршрутах читання
даних і завантаження наборів**. Профіль, заявки, погодження й адміністрування — тільки з браузера.

## Як отримати
«Профіль» → **«API-ключі»** → «Створити ключ» (`POST /api/me/api-keys`):
- ключ вигляду `gedh_<префікс>_<секрет>` показується **один раз** — разом із прикладом `curl`;
- у БД зберігаються лише **префікс** (щоб упізнати ключ у списку) і **SHA-256** — витік бази не розкриває ключів;
- **до 3 чинних ключів** (409 `API_KEY_LIMIT`); у списку видно, коли ключ створено й коли востаннє використано;
- «Відкликати» — `POST /api/me/api-keys/{id}/revoke`; видалення облікового запису відкликає всі ключі.

Створення й відкликання — `CONFIG_CHANGE` з префіксом (без секрету).

## Як користуватися
Заголовок `X-API-Key` замість входу:

```bash
curl -H "X-API-Key: gedh_ab12cd34_…" "https://gedh.vercel.app/api/datasets/<id>/observations?countries=UKR,POL"
curl -H "X-API-Key: gedh_ab12cd34_…" "https://gedh.vercel.app/api/datasets/<id>/export?format=csv" -o data.csv
```

| Що приймає ключ | Маршрути |
|---|---|
| **читання** (FR-12) | каталог, покриття, картка показника, профіль країни, значення (`observations`), вивантаження (`export`), походження |
| **завантаження** (FR-37) | `POST /api/provider/uploads` і перегляд звіту версії — **лише для ролі постачальника** (іншим — 403) |
| **не приймає** | `/me`, заявки, погодження, угоди, дозволи, адміністрування, журнал аудиту — 401 |

Права ті самі, що в браузері: закриті дані — лише в межах чинного дозволу власника ключа (AccessPolicy на кожному запиті).

## Захист
| Що | Як |
|---|---|
| частота | **60 запитів за хвилину на ключ** (NFR-18), далі 429 `RATE_LIMITED` з часом очікування |
| неправильний, відкликаний ключ | 401 `API_KEY_INVALID` |
| власник деактивований або анонімізований | 401 `ACCOUNT_NOT_ACTIVE`; при анонімізації ключі видаляються (файл 8) |
| журнал | кожне звернення записується так само, як із браузера; у `DATA_VIEW` — `channel: API`, у вивантаженні — канал `API` (`data_exports.channel`) |
| транспорт | лише HTTPS через Vercel; прямий доступ до Render заборонено (файл 6) |
